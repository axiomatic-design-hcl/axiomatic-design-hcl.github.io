Claude Code plugin

Design with the method. Write the result as .ad.hcl.

The Axiomatic Design plugin gives Claude Code two skills. A skill is a set of instructions and reference files that Claude loads for one kind of task. One skill applies Axiomatic Design to a system. The other skill writes that design as .ad.hcl files.

Install the plugin Open the repository
How the parts fit

One path from a question to a checked model

Each part has one job. The method skill makes the design decisions. The language skill writes them down without changes. The tool tests the files.

Step 1 · axiomatic-software-design

Make the design

You describe the system and the decision. Claude maps needs to FRs and DPs, builds the matrices, and reports coupling and unknowns.

Step 2 · adhcl skill

Write the files

Claude turns that design into .ad.hcl files. It keeps every FR, DP, and effect, and it adds no new facts.

Step 3 · adhcl tool

Test the files

The adhcl validate command reads the files and reports errors, gaps, and the classification of each matrix.

Skill 1

axiomatic-software-design

This skill designs or reviews a software system with Axiomatic Design. It works at the level of architecture: responsibilities, boundaries, state ownership, and contracts. It stops before classes, libraries, and code.

When to use it

Use it when you ask for Axiomatic Design, or for an independence or information analysis of a system. It is not for routine code or for general architecture questions without this method.

Start it with this command in Claude Code:

/axiomatic-design-skills:axiomatic-software-design

Then describe the system, its requirements, and the decision. Claude can also select the skill from your request.

What you get

  1. The scope, the assumptions, and a trace from each need to its FRs and DPs, with stable IDs such as N1, FR1, and DP1.
  2. A matrix for each important sibling set, with X, 0, and ?, and a reason for each effect.
  3. The classification and the design order, or the cycle and its risk when the design is coupled.
  4. Module contracts: inputs, outputs, owned state, invariants, and failure behavior.
  5. A comparison of alternatives, with the limits of the evidence.
  6. Scenarios that test the claims.

The rules that the skill follows

TopicRule
FRs and constraintsAn FR is an outcome with an acceptance criterion. A technology choice is not an FR. A hard requirement does not move into the constraints only to make the matrix diagonal.
ZigzagClaude chooses DPs at one level, then derives the child FRs inside the chosen DP. It does not build the full FR tree first and add components later.
Matrix cellsA cell is the effect of a change to the DP on the FR. It is not a call graph. An unknown cell stays ?, and the classification stays unresolved.
Whole systemClaude looks at shared state, resources, transactions, security policy, and failures across branches. A diagonal matrix in one branch does not prove independence of the whole system.
CouplingClaude first tries to remove coupling by a change of mechanism or ownership. A new service boundary or queue alone does not remove an effect.
Information AxiomInformation content is I = -log2(p), where p is the chance that all FRs succeed together. Without evidence, Claude reports it as unknown and proposes a measurement. Zero failures in a small test do not prove p = 1.
JunctionsS combines independent outcomes. C enforces the order of a decoupled design. F makes a remaining feedback loop visible, with its bounds.
references/source-notes.md

Source notes

The skill adapts Kim, Suh, and Kim (1991), Design of Software Systems Based on Axiomatic Design. The notes summarize the paper, list the changes for software architecture, and name errors in the paper's examples.

references/worked-example.md

Worked example

An invoice system with a ledger and a delivery worker. It shows a decoupled matrix, one zigzag step, a cross-branch effect, and a comparison of two candidates by joint probability.

Skill 2

adhcl

This skill turns a finished design into requirements_hcl/core/1 files. It also writes manifests and attachments, and it runs the adhcl tool when the tool is available.

When to use it

Use it to write, update, repair, or review .ad.hcl files. Use it also to convert an FR and DP hierarchy or an influence table into HCL. For design decisions, it sends you back to axiomatic-software-design.

What it does

  1. It reads its bundled copies of the language reference, the field schema, the assessment contract, and the diagnostic contract.
  2. It maps each part of the design to a block: the boundary to design, outcomes to fr, mechanisms to dp, and effects to influence.
  3. It splits a large model by domain and branch, and keeps each branch together.
  4. It puts tool bindings, behavior links, and views into attachments with a manifest.
  5. It runs the tool, fixes syntax and reference mistakes, and reports the commands and results.

What it does not do

  • It does not redesign the system.
  • It does not add a mechanism, a threshold, a module, or a probability to satisfy a profile. It reports the gap.
  • It does not write matrices, numbers, classifications, or implementation status.
  • It does not add expect blocks to force a preferred result.
  • It does not change the design to remove a finding.
  • It does not claim validation when no tool ran.

The repository includes two test prompts for this skill in plugins/adhcl/evals/evals.json. Each prompt gives a design and lists what a correct conversion must contain.

Install

Add the marketplace, then install

A marketplace is a catalog of plugins that Claude Code can install. Install Claude Code first, then run these commands in your shell.

  1. Register the marketplace from GitHub.
  2. Install the plugin.
  3. Restart Claude Code.
  4. Run claude plugin list and make sure that the plugin is enabled.
claude plugin marketplace add \
  axiomatic-design-hcl/axiomatic-design-plugin

claude plugin install \
  axiomatic-design-skills@axiomatic-design-marketplace

Data

The plugin holds instructions and reference files only. It has no connector, hook, or script that sends data to an outside service. Claude Code handles your prompts and files under its own terms.

Limits

The skills do not prove that a design is correct, and they do not replace tests. They name assumptions and unknowns so that you can test them.
